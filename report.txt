 THE ONE PRINCIPLE
═══════════════════════════════════════════════════════════════════════════════

 Every element on screen is traceable to a physics model, a trained model, or a
 deterministic function — and the operator can see which.

 Enforced mechanically, not by discipline:

   npm run validate:data    parses every JSON against Zod schemas, asserts
                            invariants I1–I16. Wired into prebuild, so a drifted
                            number FAILS THE BUILD, not the demo.
   npm run check:literals   fails if a headline figure is hardcoded in src/.
   npm run test             145 tests, also wired into prebuild.

 Three invariants are tripwires against the author, not against bugs:
   I10  rejects a ΔT outside the measured band, so the thermal scaling cannot be
        quietly tuned to produce a nicer number.
   I11  rejects a detection confidence of exactly 0.84 — the spec's placeholder.
   I12  requires the agent to justify the drone dispatch.

 FINDINGS

 1. PROJECTED 72H LOSS IS 3.07 MWh, NOT 1.44  (C16)  ← changes a number on screen
    1.44 is 0.48 × 3, where 0.48 MWh/day was itself a seed value typed into
    plan/03 §7's queue table. The integral is fully determined — no free
    parameter — and the array's 105.4 kW shortfall across the forecast curve
    integrates to 3,069.7 kWh = 3.07 MWh (1.01 MWh/day).

 2. THE 14:00 DEADLINE NEEDED A DIFFERENT MODEL  (C18)
    A single threshold crossing cannot produce 14:00: the cell-temperature curve
    peaks near 12:30, so any threshold below the peak is crossed twice and the
    afternoon crossing is the module COOLING. Implemented as cumulative thermal
    dose: T_PROP_C = 65 °C, DOSE_BUDGET_H = 5.0 h.
    The budget is SOLVED to reproduce 14:00 and declared as such — same footing as
    f_mismatch = 0.4160 and P_RATED_STRING = 49.61.
    Note the asymmetry with finding 1: the deadline model HAS a free parameter, so
    a frozen observable can be honoured. The loss integral has none, so its frozen
    value had to move.

 3. INVERTER ROWS ARE A PEER STRING COMPARISON  (C17)
    A true inverter aggregate drives 40 arrays, so B-17's fault dilutes to ~−1%
    and §2's table would show nothing. Rows are the string at the inspected
    position on each inverter — what an operator actually looks at.

 4. FORECAST AMBIENT SPREAD IS 5.7 °C, AND THAT'S THE HONEST CONSEQUENCE  (C19)
    35 °C at 10:00 and a 38.1 °C peak over-determine the curve. Kept both frozen
    numbers and stated the result rather than fudging either. It actually helps:
    warm nights mean the module never sheds heat, which is why 72 clear hours is
    expensive.

 5. C9 RESOLVED — thermal_hotspot.py now imports BASELINE_TEMP_C from physics.py.
    Only the absolute baseline changed; the ΔT matrix, coordinates, cluster count
    and σ are byte-identical because nothing in the extraction reads it.

 HEALTH INDEX, since it's non-obvious
   94 → 80 is a severity roll-up: 100 − Σ deduction[status], warning 3.0,
   critical 14.0. An energy ratio would read 99.5% (120 monitored arrays are
   ~30 MW of a 500 MW block) and would hide the difference between "dirty" and
   "about to fail". Deductions scale with fault MAGNITUDE, not the status label,
   so health is continuous — max step 4.7/frame against I16's limit of 6.

 INTERLUDE — TWO BUGS YOUR EYES CAUGHT AND THE TESTS COULD NOT
═══════════════════════════════════════════════════════════════════════════════

 You said "the fonts and everything looks weird". Both were real.

 1. EVERY FONT WAS FALLING BACK TO THE BROWSER DEFAULT
    next/font variables were on <body>, but globals.css composes them into
    --font-mono / --font-cond / --font-sans on :root (= <html>). A custom property
    that references another resolves against the element it is DECLARED on, so
    var(--font-plex-mono) was undefined at :root, --font-mono became
    guaranteed-invalid, and the whole type scale silently died.
    No error, no warning. Moving the classes one element up fixed it.

 2. TABULAR NUMERALS WERE BEING DISCARDED
    The CSS `font:` shorthand RESETS font-variant-numeric — on exactly the .t-*
    classes that carry numbers. Farm health counting 94 → 80 would have jittered.
    Every mono class now restates it, with a comment so nobody tidies it away.

 jsdom caught neither: it has no font stack and doesn't resolve the cascade.

 ALSO: the debug readout was defaulting to visible. It is a build instrument, not
 part of the product. It now defaults on in development and OFF in a production
 build — nobody watching should see a scrub bar.

 ON THE KEYBOARD, since you asked whether this is a game:
   It is a presenter remote, not a game and not a product control surface. The
   90 seconds is a recorded incident being replayed; Space/arrows/speed/R exist so
   whoever is driving the pitch can start on cue, seek back when someone asks
   "what was that number", or slow to 0.5× while talking over the thermal scan.
   In real use the product has exactly ONE input: the operator clicks APPROVE.
   That is the entire interaction surface, and it is the point of the human gate.

 THE CROSS-CHECK
   Beyond structured fields, EVERY number in the free-text reasoning is checked
   against a set built from the data itself. That is where a fabricated figure
   actually hides: the reference implementation's own agent output says "matching
   the client-reported 60% output drop" while its telemetry says 58.4%, and
   nothing caught it. This would have.
   A stage that fails is retried with the rejection as a correction; after four
   attempts the script exits non-zero and writes NOTHING.

 IT CAUGHT FOUR THINGS — THREE WERE MY ERRORS, NOT THE MODEL'S
   1. It flagged "17" out of "B-17". Identifiers contain digits that aren't
      measurements. A check that cries wolf is a check that gets switched off.
   2. I demanded suspectComponent == "INV-B". The model answered "String
      B-17-S3", which is MORE precise — the fault is inside the string, INV-B is
      only where it is observed. I was forcing a worse answer.
   3. prognosis.confidence came back as 5, which Zod rejects.
   4. THE GENUINE CATCH: my prompt exposed THERMAL_SPAN_C as a bare "25 C span",
      and the model wrote that the cells run "2.8 °C above the nominal 25 °C
      span" — two REAL numbers in a physically WRONG sentence. Numeric checks
      can't see that. Removed the loose number; it now correctly says
      "2.7–2.8 °C above the array median".

   Also tightened severity: the model first said "medium", which would have sat
   beside a console badge reading CRITICAL. A >50% string shortfall with a
   same-day deadline isn't medium — diagnostic ambiguity belongs in confidence.

 typographic() swaps the ASCII hyphen the model writes for U+2212 so agent prose
 matches the tables beside it. GLYPH ONLY — no word, digit or unit altered, and it
 will not touch B-17 or INV-B. That last case has its own test, because silently

 THE IRONBOW CONSISTENCY CHECK - the item plan/05 names for this phase
   The seven stops existed in THREE hand-typed copies: globals.css tokens, a
   nearest-stop lookup in AnomalyMatrix, and vec3 literals in the GLSL shader.
   Nothing compared them. A drift of one stop would have broken the project's one
   aesthetic bet SILENTLY - nothing would look broken, it would just stop meaning
   anything.
   Now src/lib/ironbow.ts is the only definition. The matrix calls it; the shader
   is GENERATED from it; and ironbow.test.ts READS globals.css OFF DISK and fails
   if a token has drifted. 18 tests, including that the GLSL and the TypeScript
   interpolate identically across the whole domain to within one rounding step.
   Fixed while there: the matrix used arbitrary delta-T thresholds. The domain is
   now the measured range (-6.5 .. +3.2 C), so the hot band lands in the amber end
   where a thermographer expects heat.

 A REAL ACCESSIBILITY BUG
   Every control used `all: unset` as an INLINE style. Inline styles outrank the
   stylesheet, so that also unset the focus outline - and no :focus-visible rule
   could restore it. Keyboard users had no visible focus anywhere in the app.
   Replaced with a .btn-reset class carrying its own focus ring. All three
   controls are real <button> elements and are reachable on Tab.

 prefers-reduced-motion
   The CSS media query cannot reach framer-motion's JS-driven animation, and the
   feed's slide-in is JS-driven. Wrapped in <MotionConfig reducedMotion="user">.
   The MATRIX FILL deliberately still runs - it is information, not decoration.

 SCENE PALETTE
   plan/04 bans raw hex in src/components/. All remaining hex was in the 3D scene,
   where three.js materials cannot read CSS variables - and the panel blue was
   written out twice. Pulled into src/lib/scenePalette.ts, every value cited to
   CLAUDE.md section 14.

 MOTION AUDIT - clean. No springs, no bounces, no easing on anything that carries
   meaning. Every transition is linear, 120-200 ms. The two CSS animations (REC
   pulse, reticle breathe) are presentational and no selector reads them.

 TEST HARNESS
   The PiP assertion was timing out at 5 s as the console got heavier. Replaced
   with a STRONGER and cheaper one: the console's entire rendered text must appear
   inside the cinematic's as one contiguous run, since the PiP renders ConsoleRoot
   whole. A screenshot, a mock or a simplified copy all fail it.
   Also silenced jsdom's canvas "Not implemented" noise, which the WebGL probe
   could not catch and which was burying real output.

 Written after an audit of what was NOT built. The list itself is now a document
 that ships: docs/backlog.md, kept current, replacing two stale and contradictory
 "Post-project TODO" sections in the README that between them claimed the product

 1. CONTROLS THAT WERE PROPS

    Six controls were lifted off the reference screenshot and never wired. They
    sat where controls sit, they looked like controls, and every one did nothing.

      QUEUED              was a bordered box among two buttons. It is a STATUS,
                          so it is now rendered as one - NOT QUEUED / v QUEUED -
                          rather than as a third thing you can press.
      INSPECT EVIDENCE    a real button. Scrolls the rail to the inspection group.
      OVERRIDE            a real control, and the other half of the approval gate.
                          A gate with only a yes is not a gate, it is a delay. It
                          records the operator's decision WITH a reason, shows it
                          on screen, and can be cleared. It raises no work order -
                          declining is not approving.
      FILTER              cycles the event feed's severity floor: all / warning+ /
                          critical. It filters the FEED and deliberately not the
                          mission log, because hiding rows from a list is a choice
                          about a list; making the drone stop reporting what it
                          found is a different thing.
      VIEW ALL EVENTS     expands the feed past its six-row preview, and says how
                          many rows that is.
      VIEW QUEUE ->       navigates to the Repairs screen. It has sat next to a
                          working repairs module since Phase 13.

 2. ONE FAULT WAS NEVER ENOUGH TO USE THE CONSOLE WITH

    data/scenario.json carried a single event. An operator could look at exactly
    one interesting array and 119 identical healthy ones, so nothing could be
    compared against anything and most of the console could not be exercised at
    all.

    THREE CRACKS, THREE DEPTHS. The same mechanism - a cracked cell driving its
    bypass diode into conduction - separated by how many of the array's seven
    strings the crack has reached and how far the mismatch derate falls:

      A-31  11:20   2 of 7 at 0.68     string -32.0%   array  -9.1%   warning
      B-17  10:04   5 of 7 at 0.4160   string -58.4%   array -41.7%   critical
      C-07  12:40   6 of 7 at 0.34     string -66.0%   array -56.6%   critical

    B-17's pair is untouched. It is the array the committed evidence, the cached
    agent run and every invariant describe, and it does not move.

    evaluateArray gained faultedStrings and terminalMismatch as PARAMETERS,
    defaulted to B-17's frozen pair - so the golden test that recomputes the whole
    committed telemetry.json from the TypeScript is byte-identical, and a crack is
    no longer one size.

 3. INJECTION, AND WHY IT IS NOT A BACK DOOR

    A sixth module screen - SCENARIO - injects a fault onto any array on demand:
    four mechanisms (hairline / established / advanced crack, string outage), a
    ramp, a live preview of the deviation the physics WILL produce.

    It writes a SCENARIO EVENT and nothing else. There is deliberately no way to
    type a deviation onto an array. Everything that then appears - output,
    deviation, status, cell temperature, queue position, the event feed line - is
    computed by the same model that evaluates the committed faults. That is the
    difference between a test case and a fabrication, and the whole project rests
    on it. injection.test.ts asserts the injected object's key set exactly, so a
    future field that smuggles in a reading fails the build.

    Injected faults are marked wherever they surface: in the feed, in the verdict
    block, in the queue. A rehearsal presented as site history would be the same
    class of lie as B-17's evidence shown under another array's name.

 4. THE RIGHT RAIL NOW MAKES AN ARGUMENT

    Reported: "too much info, seems unorganised, not telling a story". Correct.
    It was twelve peer sections in the order they were BUILT, and on a healthy
    array the first thing it said about C-29 was a three-line paragraph about
    something it did not have.

    Five groups, in the order an operator reasons:

      STATE       what the array is doing, measured
      ASSESSMENT  what the agent makes of it, and when it said so
      INSPECTION  what a drone was sent to find out, and what came back
      OUTLOOK     what the weather does to it over 72 hours
      DECISION    what the operator is being asked to authorise

    Each group is one claim; blocks inside it are the evidence. A block with
    nothing to say is absent rather than apologetic - "no capture on file" went
    from being a section header to one sentence at the point where the imagery
    would have been.

 5. FOUR UNTRUTHS IN ONE SCREENSHOT

    The reported C-29 panel had, in one view:

      "Inspected - evidence captured"  directly above  "no capture on file"
          Two flatly contradictory statements four lines apart. The mission proves
          the drone went and looked; whether committed imagery came back is a
          separate fact and is now stated separately.

      Output 0.00 kW / Expected 0.00 kW / Irradiance 0 W/m2 at 35.6 C ambient
          That is night. The deviation formula divides zero by zero, floors to
          0.0%, and statusFor calls it HEALTHY - so a cracked array would read
          clean all night. The console now says NO GENERATION - AFTER SUNSET and
          withholds the deviation rather than printing arithmetic on two zeroes.

      Fleet health climbing back toward 100 after dark
          Terminal status was evaluated at the CURRENT hour. It is now evaluated
          at reference conditions: a fault is a property of the array, not of the
          time of day.

      "Projected loss 3.07 MWh / 72 h" under a healthy array
          B-17's committed integral printed under every array in the site. Now
          scaled by the selected array's own shortfall at reference conditions -
          B-17 still reads exactly 3.07, and C-29 reads "none - C-29 is not
          deviating".

    Related, found while fixing it: the live event feed sourced EVERY fault on the
    site to "PANEL B-17", because the EventSource enum in types.ts contained that
    literal and would not let it say anything else. It is now the fixed subsystem
    names plus PANEL <id> for any array. Mission events were sourced to DRONE 01
    regardless of which drone flew.

 6. THE LIVE QUEUE STOPPED DROPPING WORK, AND STOPPED EMPTYING AT NIGHT

    A crack's deadline is COMPUTED - the hour its cumulative time above the
    propagation threshold reaches the declared dose budget - which is the entire
    claim the prognosis stage makes. The queue nevertheless LOOKED IT UP, and only
    B-17 had a committed record, so a second cracked array fell out of the queue
    and was reported as "unrankable". Nothing about it was unrankable; the
    deadline was never asked for. crackDeadlineHour() now computes it, in
    TypeScript, reproducing the Python's 14:00 for a fault beginning at the epoch.

    The queue also read its shortfall off the live frame, so at sunset it emptied
    completely and refilled at dawn. It now quotes shortfall at REFERENCE
    conditions: a cracked array costs the same at midnight; the sun is simply not
    up to prove it.

 7. LIVE_AGENT - THE FLAG THE SPEC PROMISED AND NOBODY BUILT

    CLAUDE.md sec 3 and sec 9.4 both describe it. There were zero references to it
    anywhere in the repo.

      unset / false   verify the COMMITTED cache against current telemetry and
                      forecast. No network, no tokens. Every numeric field and
                      every number in the prose goes through the same cross-check
                      a fresh run would.
      true            call Groq and rewrite the cache.

    Off by default, because the question that actually goes stale is not "did the
    model answer" but "does the committed answer still agree with the physics" -
    and that is answerable offline. It catches a regenerated telemetry.json
    silently invalidating the cached prose, which nothing previously did.

 8. THE AGENT CARD SAYS WHEN IT SPOKE

    Flagged at the end of Phase 14 and fixed here. Triage runs once per array and
    the site keeps moving, so its figures drift from the ones in STATE above it.
    That is correct behaviour and it reads as two systems contradicting each other
    unless the card is stamped. It now carries "as at HH:MM", and past half an
    hour of site time it says so explicitly.
